## Decisions taken inside the task (for the verifier)

1. **Gate refusal is its own rule, placed before `chunking`** (addendum item 4). Under the prompt's order, 016:B and
   018:B would have been `chunking`, because their section was hit but no required-point quote was whole in a chunk.
   The gate fired, so the LLM never saw the chunks. The chunking signal is kept as a secondary tag. This is a rule, not
   an `override_reason`.
2. **The `citation` stage cannot fire under the §2 trigger.** A correct answer enters the failure set only with
   section hit@5 = 0, and `retrieval_miss` takes it first. The trigger was not widened, since that would change the
   stage × arm table. The three correct answers with a citation defect are listed separately
   (`citation_defects_on_correct_answers`: 005:A, 015:A, 009:B).
3. **`retrieval_miss` = section hit@5 = 0.** On a two-slot case this means one slot has no top-5 chunk; the rule text
   shows the slot fraction (022:A, 030, 031:B are 0.5). `correct_refusal` is a success. Unlabelled records are not
   classified.
4. **Paired n per row.** An answer-level row pairs only the cases labelled in both arms, which gives 35 labelled cases
   in total (addendum item 1): 31 answerable for accuracy, lenient accuracy and false refusal, and 4 for correct
   refusal and hallucination. Groundedness 27 and citation 27/28 need an answer check in both arms. Generate latency
   and tokens 30. Retrieval rows 32.
5. **Latency:** `embed_query` and `total` are shown as per-arm medians but **not tested**, because Arm B's query
   embeddings were cache hits (EVAL-004a). This is added as a threat paragraph beyond the addendum's four, together
   with "one run per arm".
6. **Discordant set** = answer label or groundedness differs (both labelled), or any retrieval metric differs (hit@1/3/5
   source/section lenient + strict, evidence hit@1/3/5, MRR lenient + strict). That gives 23 cases, all explained in
   the report's table. Groundedness was added after I saw that 005 and 026 differ on it.
7. **`language` tag:** only the 7 EN/VI parallel pairs can carry it (a VI case needs an EN twin).

## Explain it back

- **Why a paired design and paired tests.** Both arms answer the same 36 questions. Comparing each question with itself
  removes question difficulty from the comparison, so only the chunker differs. McNemar counts only the questions
  where the arms disagree (b = A-only, c = B-only), and Wilcoxon does the same for numbers. The alternative is
  unpaired rates, e.g. a two-proportion test on each arm's accuracy. It would ignore that most questions are right in
  both arms, and it would need far more questions to see the same effect.
- **What "no statistically reliable difference" means here.** Accuracy has only 5 discordant pairs. Even a 5–0 split
  gives p = 0.0625, so the test cannot reach 0.05 at this n. The result is "too few disagreements to tell", not "the
  arms are equal". The bootstrap CI (Δ +0.032, [−0.097, +0.161]) shows the plausible range.
- **Why the chunker mostly moves evidence around instead of finding or missing sections.** Both arms embed the same
  heading-path prefix, and A's sections are already close to 1,600 chars (p90 1,527). So section hit@5 is equal
  (0.938). What differs is whether one chunk holds the whole answer:
  - A wins single-section questions (009, 015, 018, 027);
  - B wins answers that span adjacent short sections or a tiny doc (003, 011/012, 022).
- **Why several "arm differences" were not credited to the chunker.**
  - 001 is the gate threshold: 0.686 was tuned on Arm A, and the scores were A 0.6779 vs B 0.6908 for the same
    section.
  - 020 depends on one judge point grade that the owner's blind grade reverses.
  - 005/026 groundedness are judge reasoning errors (visible in the judge's own reason text).

  Reading the chunks and the judge's reasons is what separates a chunking effect from a measurement effect.
- **Why the failure rules are a script with an override column.** Deterministic rules make the stage × arm table
  reproducible. The verifier can re-run it byte-identically, and a manual read can still correct a label, but only
  with a written reason. The gate rule sits before `chunking` because a gated record never reached the LLM. The
  alternative, a hand label per failure, is faster but cannot be checked.
