## Design decisions
- **Structure test.** It only forbids `google`/`httpx`/`chromadb`/`markitdown` in presentation, so `app.py` *could* import `composition`. I still put every `composition`/`infrastructure` import in `wiring.py` and added a test that nothing else in presentation has one: the view-model, view, adapter and fake stay clean, and the exception to "presentation → application → core" is one reviewable file.
- **One `AnswerQuestion` per arm, lazy, shared throttles.** One `GeminiLLM` for both arms (its throttles are per instance); `CoreAskQuestion` builds each arm's service on first use under a lock. The window opens with a missing index/key; the error shows on the first question.
- **Per-call embedder (deviation from "build once").** `CachingEmbedder` holds a `sqlite3` connection, which only its creating thread may use, and `QThreadPool` runs each question on any free worker. Found by reading `embedding_cache.py`, before running. `PerCallEmbedder` opens/closes the cached embedder per query: safe on any thread, costs a file open, a cached text still spends no request. The live run below used three questions on the pool.
- **`ALLOW_FALLBACK` true** by `replace(settings, allow_fallback=True)` passed to `GeminiLLM`, not by mutating the environment.
- **Errors.** `LLMError.kind` 1:1 (quota/unavailable/other); `RetrievalError` and `VectorStoreError` → `no_index` (`open_vector_store` raises `VectorStoreError` for a missing collection, the real "no index" case; the addendum names only `RetrievalError`); `GenerationError`, `ConfigurationError`, `EmbeddingError`, anything else → `other`. `other` shows "Something went wrong: <message>"; core messages never contain the key.
- **The 7 RAG-002 mismatches:** 1 `related_only = insufficient`; 2 `model_used` from `llm`, `None` when the gate answered (+ `fallback_used`); 3 port shape: `CoreAskQuestion.ask(question, arm)` picks the arm's service; 4 error map above; 5 no `generate` key when the gate answered (nothing invented); 6 core-only fields dropped; 7 `source_url` both `str`. Each has a test in `test_core_adapter.py`.

## Explain it back
- **Why one adapter and a `wiring.py` seam?** The view-model only knows `contracts.py`; the core result shape lives in one mapping function, so a core change touches one file. `wiring.py` is the single place presentation meets the composition root, and a test pins that. Alternative: import core `AnswerResult` in the view-model, or let `app.py` build everything: the GUI would then know infrastructure and core types everywhere.
- **Why `related_only = insufficient`?** Owner decision D2: an insufficient answer may show related passages, but they must never look like the answer. Core has no such flag, so the adapter derives it.
- **Why a per-call embedder?** SQLite connections are thread-bound and the pool moves work between threads; opening per query is safe by construction. Alternatives: a single-thread executor (relies on Qt keeping that one thread alive) or `check_same_thread=False` (changes shared infrastructure).
- **Why does `LLMError.kind` map 1:1 and everything else become `other`?** RAG-003 wrapped provider errors in infrastructure, so the GUI sees three kinds without importing `google`/`httpx`; only a missing index gets its own message. An error is never turned into a refusal.
- **Why does the gate refusal cost 0 LLM requests and show "model: none"?** The retrieval gate (OD-9) returns before generation; the status line says so instead of inventing a model or a `generate` latency.
