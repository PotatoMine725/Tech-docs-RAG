## Explain it back

- **Why this task made zero Gemini calls.** Every number in the report comes from the two run folders EVAL-004a
  already produced and committed (`records.jsonl`, `judgements.jsonl`) plus the owner's already-graded spot-check
  sheet. Generating tables and prose from data that already exists on disk needs no new model call — the EVAL-003c
  tools (`make_tables.py`, `score_spot_check.py`) are pure offline readers/renderers by design, precisely so a
  reporting task like this one never touches the API or the daily quota.
- **Why `score_spot_check.py` only auto-lists S09/S10 as disagreements, and S03 had to be added by hand.** The
  tool's rule-based comparison is label-level: it runs the owner's per-point grades through `map_result` and reports
  a disagreement only when the resulting *label* differs from the judge's. S03's owner grade (`no` on P2) and the
  judge's (`partial` on P2) both still map to `partially_correct` — same label, different point — so the tool
  correctly leaves it out of the label-level confusion matrix and disagreement list. It is a real, already-recorded
  disagreement (EVAL-004a) at a finer grain than the tool measures, so it belongs in the prose, not a bug in the
  tool.
- **Why the appendix is a separate file, not embedded in the report.** The brief's 5 columns include the full
  question text and the full generated answer for all 72 records; inlining that (~72 KB) would make the report
  itself the least readable part of the deliverable. The two per-arm CSVs already satisfy the brief structurally
  (one row per case per arm, the exact 5 fields); the combined Markdown file exists only because the task asked for
  a Markdown appendix specifically, not because the CSVs were insufficient on their own.
- **Why `section_precision` (0.977) can be below `source_precision`/`auto_class` (both effectively 1.000/58 of 58)
  without any record actually failing the citation check.** `auto_class` is a discrete bucket (does *any* citation
  point at the right source with *acceptable* evidence — a lenient pass/fail), while `section_precision` is a
  continuous per-record mean over *all* of that record's citations. A record with 2–4 citations where only one
  lands in the wrong heading section still buckets as `correct_evidence` (the other citations carry it) but pulls
  its own precision mean below 1.0 — the two metrics are answering "did it cite well enough" vs. "how precisely",
  and they can disagree because one is lenient-discrete and the other is exact-continuous by construction (OD-12).
- **Why the EN/VI accuracy gap is a refusal-rate story, not a comprehension story.** Retrieval and citation numbers
  are close between languages (`source_hit@5`/`section_hit@5` 0.969/0.969 EN vs. 0.938/0.906 VI); the accuracy gap
  (0.812 vs. 0.645 strict) is explained almost entirely by 5 of 6 `false_refusal` records being VI. That points at
  the retrieval gate's threshold interacting with VI-chunk scoring (or VI query embeddings scoring slightly lower
  against the same English-language corpus), not at the answer model failing to understand Vietnamese once it
  actually answers — a different fix (gate threshold or per-language calibration) than "the model doesn't read
  Vietnamese well" would imply.

## Appendix A: `tmp_render_appendix.py` (scratch, verbatim, not committed as code)

Run after `make_tables.py`: `.venv\Scripts\python.exe tmp_render_appendix.py` (from the worktree root; reads the two
just-generated `eval-table-<run_id>.csv` files, writes the joined Markdown table).

```python
"""EVAL-004b scratch: render the two eval_table CSVs (make_tables.py output) into one Markdown appendix table.
Reads only the generated CSV files; no new numbers, just formatting/joining.
"""
import csv
from pathlib import Path

RUNS = ["20260928-eval-A-full-491f137", "20260928-eval-B-full-491f137"]
RESULTS = Path("data/evaluation/results")
COLS = ["case_id", "arm", "language", "question", "expected_answer", "expected_source", "generated_answer", "result"]


def esc(s: str) -> str:
    return (s or "").replace("|", "\\|").replace("\n", "<br>")


def main() -> None:
    rows = []
    for run_id in RUNS:
        with (RESULTS / f"eval-table-{run_id}.csv").open(encoding="utf-8", newline="") as fh:
            rows.extend(csv.DictReader(fh))
    rows.sort(key=lambda r: (r["case_id"], r["arm"]))
    out = ["| " + " | ".join(COLS) + " |", "| " + " | ".join("---" for _ in COLS) + " |"]
    for r in rows:
        out.append("| " + " | ".join(esc(r[c]) for c in COLS) + " |")
    print(f"rows: {len(rows)}")
    (RESULTS / "eval-table-eval-004-appendix.md").write_text("\n".join(out) + "\n", encoding="utf-8")
    print("wrote", RESULTS / "eval-table-eval-004-appendix.md")


if __name__ == "__main__":
    main()
```
